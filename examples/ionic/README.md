# ionic: Ionic Framework core on Stencil v5, the proving ground for stencilrs

[Ionic Framework](https://github.com/ionic-team/ionic-framework)'s `core` (MIT, 94 components, per-mode
iOS / Material Sass, the largest open-source Stencil code base) is the real-world test subject for stencilrs.
This folder fetches it, migrates a copy to Stencil v5, builds it with `stencil build` and with stencilrs'
Vite plugin, and checks both in headless Chrome. `npm run bench` benchmarks all three builds (below).

Ionic's source is **never committed** (see `THIRD_PARTY_NOTICES.md`). Everything under it is generated from
upstream plus the checked-in codemod, so the whole thing is reproducible.

```sh
npm ci --ignore-scripts      # Stencil 5.0.0-beta.25, @stencil/sass, ionicons, Playwright
npm run fetch                # clone ionic-team/ionic-framework @ v9.0.12 into upstream/
npm run migrate              # upstream/core -> migrated/ (Stencil v5 source)
npm run build:stencil        # stencil build (v5) -> dist-stencil/, plus css/ and docs.json
npm run smoke                # load dist-stencil in headless Chrome, ios + md, screenshots in smoke/shots/
npm run build:stencil4       # the stock Ionic 9 / Stencil 4.45.4 build -> dist-stencil4/ (reference row)
npm run build:stencilrs      # the same migrated/ source through @popcorn245/stencilrs/vite -> dist-stencilrs/
npm run check                # both builds in headless Chrome: smoke, screenshots, all 94 components, no fallbacks
npm run all                  # fetch, migrate, build:stencil, smoke
npm run build:ssr            # stencil build with only { type: 'ssr' } -> dist/hydrate-stencil/index.js (hydrate app, for bench:ssr)
npm run bench:ssr            # server-side rendering benchmark (below)
npm run bench                # cold/warm build, dev server, watch rebuild, per-file transform, memory, size -> site/data/benchmarks-ionic.json
```

`npm run smoke -- stencil4|stencilrs` runs the same page against the Stencil 4 build. `--shots <dir>` moves the
screenshots. If the Chromium Playwright expects is not installed, point `CHROME_PATH` at any Chromium
(`npx playwright install chromium` is the proper fix).

Both builds are cold (`enableCache: false`), build the same bundles with the same three output targets (lazy
loader, standalone custom elements, `docs-json`) and write to the same layout, so #65 can time them side by
side. `build:stencil` writes `logs/stencil.log`, `build:stencil4` writes `logs/stencil4.log`; the Sass
deprecation warnings Ionic's `@import`-based Sass triggers (about 80,000 lines per build) are kept in the log
and filtered from the console.

## What was changed in Ionic, and why

Starting point: `core/` of v9.0.12, which Ionic builds with Stencil 4.45.

**Left out of the copy** (`scripts/copy-core.mjs`): `*.spec.ts(x)`, `*.e2e.ts`, every `test/` and `e2e/` folder
(Jest and Playwright tests and their demo pages), `jest.d.ts`, `eslint`, Docker and Vercel files, and
`src/components.d.ts`. The last one is generated by Stencil; upstream's imports `@stencil/core/internal`, which
v5 does not have, so letting it seed the v5 build made every `HTMLIon*Element` type collapse (400+ TypeScript
errors).

**Config** (`config/stencil.config.v4.ts`, diffable against upstream's `core/stencil.config.ts`): the Angular,
React and Vue output targets, `docs-vscode`, `dist-hydrate-script`, the api.txt generator and the Jest `testing`
block are dropped (they write outside `core/` or are not measured), and `docs-json` goes to the build folder.
The bundles, Sass plugin, preamble, global script and `extras` are Ionic's own. The Stencil 4 reference build
uses this same file.

**`stencil migrate`** (Stencil's own codemod, v5.0.0-beta.25) does most of the work: 84 items in 78 files.

| Rule | Items |
|---|---|
| `shadow: true`, `scoped: true`, `shadow: { delegatesFocus: true }` to `encapsulation: { ... }` | 77 |
| `dist` to `loader-bundle`, `esmLoaderPath` to `loaderPath`, `dist-custom-elements` to `standalone` | 3 |
| `extras` to `compat`, `experimentalSlotFixes` removed (`lightDomPatches` is on by default), `enableImportInjection` and `externalRuntime: false` dropped | 4 |

**Our patches** for what it leaves (`scripts/migrate.mjs`, `scripts/patches.mjs`; each must match exactly once,
so an upstream change fails loudly):

1. **`enableCssOnlyComponents: false`.** v5 treats every `.scss` file under `src` as a possible CSS-only
   component and runs Sass on each partial on its own. Ionic's `*.vars.scss` partials rely on variables their
   importer defines, so 12 of them fail with "Undefined variable".
2. **`experimentalScopedSlotChanges`** is removed from the migrated config: `stencil migrate` leaves it in
   `compat`, but v5 has no such option.
3. **tsconfig**: `baseUrl` is an error in TypeScript 6, so it is removed and `src/*` is mapped in `paths` (a
   few files import `src/interface` bare).
4. **JSX is a `VNode`, not an `HTMLElement`.** Three places typed JSX as DOM nodes (`checkbox.tsx`
   `getSVGPath`, `spinner.tsx` `svgs`, `select-option-render.tsx` `renderOptionLabel`) now say `any`.
5. **Invalid CSS that v4 passed through.** v5 parses styles with lightningcss and rejects what browsers
   already ignored. Fixed to what the code obviously meant: `item-divider.ios.scss` (missing comma between two
   `::slotted()`), `item-divider.md.scss` (`::slotted(h3, h4, h5, h6)`), `segment.scss`
   (`:host(.x::-webkit-scrollbar)`), `tab-button.ios.scss` (`::slotted(ion-icon::before)`),
   `accordion-group.md.scss` (`::slotted(x):first-of-type`). The `rtl()` mixin in `ionic.mixins.scss` also
   emitted `.a::before:dir(rtl)`; it no longer emits `:dir(rtl)` rules for selectors with a pseudo-element
   (browsers dropped those anyway). In `ionicons`' `icon.css`, `@supports not selector(a) and selector(b)` is
   parenthesised by a Stencil plugin (`config/ionicons-css-fix.ts`), because that file lives in `node_modules`.
6. **`package.json`** is replaced by a minimal one (v5 validates it against the build output).
7. **Packages**: Ionic's devDependencies the build type-checks against (`@capacitor/*`, `ionicons`, `sass`,
   `tslib`) are pinned in this folder's `package.json`, so nothing is installed inside `upstream/`.

Items 4 and 5 are things any real library moving to v5 will hit; they are the list of v5 incompatibilities
stencilrs has to behave the same on (or report).

## Ionic through stencilrs (`build:stencilrs`, `check`)

`vite.config.ts` builds `migrated/` with `@popcorn245/stencilrs/vite` (Vite 8, `verbose: true`) into
`dist-stencilrs/`: `ionic.js`, one ES module that runs Ionic's global script (`initialize()`, first: defining a
component upgrades the elements already in the page, and they read their mode at once), defines `ion-icon` from
`ionicons/components/ion-icon.js`, and registers the 95 files that declare a component (the 94 tags of `docs.json` and the internal
`ion-select-popover`); `css/`, Ionic's global stylesheets (compressed Sass, byte for byte what
`build:stencil` writes). Sass for the `.ios.scss` / `.md.scss` mode styles is the plugin's own pipeline. The build
takes about 5 s (`stencil build`: about 30 s) and the log says `compiled 95 component file(s), reused 0; 0 left to
Stencil's compiler`.

`npm run check` (`check/run.mjs`) needs both builds and a Chromium (`CHROME_PATH`, or `npx playwright install
chromium`; without one it skips the browser steps, `IONIC_REQUIRE_BROWSER=1` makes that an error):

1. no file fell back to Stencil's compiler (reads `logs/stencilrs.log`);
2. `smoke/run.mjs` on `dist-stencil` and `dist-stencilrs` (button, card, list, toggle, modal; ios and md);
3. the four smoke screenshots of the two builds, pixel by pixel (identical);
4. every tag of `docs.json` plus `ion-select-popover` (internal) and `ion-icon`, mounted in both modes in each build: defined, hydrated, a shadow root
   exactly where the encapsulation says (shadow, scoped, none), scoped components carry their `sc-*` class,
   no console error or page error (Ionic's own "must be used inside ion-content" style diagnostics for a bare
   element are expected, and must be the same in both builds);
5. the two builds against each other: same host and shadow DOM, same size, same scope ids in the styles, and the same CSS text in every component stylesheet but the two listed in `CSS_DIFFERENCES`.

### What stencilrs got wrong on Ionic, and what changed

Found by this build, fixed on this branch (each has a test):

| Finding | Fix |
|---|---|
| A file that is not a component (a util, Ionic's global script) importing `getMode`, `setMode`, `writeTask`... from `@stencil/core` got `@stencil/core`'s own minimal client, not the runtime the compiled components use: `setMode()` never reached them and no mode stylesheet loaded | `vite.js` resolves a bare `@stencil/core` to `@stencil/core/runtime/client/standalone` (as `stencil build` rewrites it) |
| `useDefineForClassFields: false` in the tsconfig (Ionic sets it): Vite's own TypeScript transform reads it too, and moves every field of the already compiled component into the constructor ahead of `__registerHost()`: no `@Prop` kept its default (`buttonType` undefined, `undefined-solid` classes) | stencilrs honours the option as Stencil does: the new `useDefineForClassFields` transpile option, set from the tsconfig by the plugin; initializers become assignments after `__registerHost()` / `__attachShadow()` and the events, uninitialized fields are dropped |
| Mode stylesheets of a scoped component were scoped to `sc-<tag>` while the runtime puts `sc-<tag>-<mode>` on the host: no scoped rule applied (`ion-buttons` 0 px tall, `ion-label`, `ion-input` and others the wrong size). `@stencil/unplugin` does the same | `vite-css.js` scopes to `sc-<tag>-<mode>` (the ui-kit's `compare:css` allows exactly this one difference) |
| `::slotted(*) h1` (valid only in a scoped component, which rewrites it) made lightningcss throw, with no file name in the error | a stylesheet lightningcss rejects is scoped first for a scoped component, as `stencil build` does; errors name the file |
| `import('sass')` and the other CSS packages resolved from the plugin's own folder, not the project's: a `file:` / linked install found none | imported from the project first |
| The runtime's `BUILD` defaults have `hydrateClientSide: true`, so scoped hosts got an extra `sc-<tag>-<mode>` class | new plugin option `buildFlags`: this build sets `{ hydrateClientSide: false }`, as `stencil build` does without a hydrate target |

CSS text (issue #72): the Vite path used to lower CSS through lightningcss without browser targets and with its own
minify, so 30 to 31 of the 96 component stylesheets differed from `stencil build` (`:dir(rtl)` without Stencil's
`:lang()` fallbacks, no `-webkit-` prefixes, `background: none` as `0 0`, `bold` as `700`, `(min-width: 576px)` as
`(width >= 576px)`, `translate3d(x, 0, 0)` as `translate(x)`, which dropped the compositing layer and is why the ios
toggle's edges differed by a few levels). The plugin's `css` option now defaults to Stencil's autoprefix targets and
a whitespace-only minify. `check` compares the CSS text and the screenshots strictly: the screenshots are identical
pixel for pixel, and all but two stylesheets are identical CSS text. The two (`CSS_DIFFERENCES` in `check/run.mjs`):
`ion-icon` (ionicons' prebuilt component, not this plugin's CSS) and the md `ion-select` (a selector Sass writes
twice, which Stencil's own minifier deduplicates). The Sass deprecations are silenced with the plugin's
`css.sass.silenceDeprecations` (`vite.config.ts`); `scripts/build.mjs` still filters them for the two
`stencil build` targets, whose Sass plugin cannot be configured from here.

## Ionic's hydrate app from stencilrs (`build:hydrate`, `check:ssr`)

`npm run build:hydrate` builds the hydrate app (`renderToString` / `hydrateDocument`, what `stencil build` makes with an
`ssr` output target, `npm run build:ssr`) from the same `migrated/` source compiled by stencilrs, to
**`dist/hydrate-stencilrs/index.js`** (the SSR benchmark, `bench-ssr.mjs`, loads it from there). The assembly is
`buildHydrate` of `@popcorn245/stencilrs/ssr` (`ssr.js`); `scripts/hydrate-options.mjs` is what is Ionic's: the tsconfig
`paths` aliases, the global script, the preamble, the namespace, and `collections: ['ionicons']`: Stencil's `ssr`
target also compiles `ion-icon` from the collection ionicons ships (plain JavaScript with the decorators gone), so the
adapter in `ssr-collection.js` writes its decorators back from the static metadata. The app has 96 components: the 94 tags of
`docs.json`, the internal `ion-select-popover` and `ion-icon` (the 95 files that declare a component, plus ionicons').

Component styles go through the plugin's `css.minify: 'stencil'`: Stencil's own order (scope, autoprefix, its CSS
serializer, newlines as spaces), which is what its hydrate app embeds; the plugin's default (lightningcss, whitespace
only) is for the client bundle. With it the stylesheets are identical text, and so is the HTML.

`npm run check:ssr` (`check/ssr-parity.mjs`) renders the bench pages (`ssr-pages.mjs`: fragment, list-50, kitchen-sink) in
`declarative-shadow-dom` and `scoped` with both apps and asserts the HTML is byte-identical (also with
`fastSerializer: false`), that every component is registered, and hydrates the kitchen-sink page in Chromium (content with
JavaScript off, the server's elements adopted by the client bundle of `build:stencilrs`, a toggle clicked).

On Windows, `config/stencil.config.ssr.ts` works around a Stencil 5 bug (#146). Stencil's `@stencil/core/app-globals`
module imports the global script (`src/global/ionic-global.ts`) by a forward-slash absolute path (`J:/…`). The
components' relative imports of the same file resolve to the backslash path (`J:\…`). The bundler keeps two copies, so
`initialize()` sets the mode on a copy no component reads, and Stencil's hydrate app renders `class="undefined"`
where it should render `class="md"`. A small `resolveId` plugin in that config rewrites a forward-slash absolute Windows
path to its backslash form, and it does nothing on other platforms. stencilrs does not need it.

## Benchmark (`npm run bench`)

`bench.mjs` times the three builds against each other and writes every raw sample, the machine and the versions to
`../../site/data/benchmarks-ionic.json`, which the Benchmarks page of the site renders (method, caveats and tables are there).
It fetches, migrates and prepares the Stencil 4 toolchain itself if they are missing, and takes about 50 minutes at the default
10 runs (`--runs N`, `--rows`, `--steps`, `--out`, `--preview`; `--help`). Each step has a timeout; every child is in its own process group and is
killed with its tree on exit, Ctrl-C or timeout (dev servers included); ports are chosen free; the edited `button.tsx` is restored on every exit path.
For the benchmark the configs read `IONIC_STENCIL_CACHE=1` (Stencil's cache on, so a warm build can use it); `build:*` leave it off.
`.bench/` (git-ignored) holds the outputs.

Besides the three builds the bench has two like-for-like rows, for cold and warm builds only: `stencil-standalone` (`stencil build --config stencil.standalone.config.ts`,
copied from `config/stencil.config.standalone.ts` by `npm run migrate`: only the `standalone` output target) and `stencilrs+check` (`vite build` with
`IONIC_DTS=1`, i.e. `dts: true`, run beside `tsgo --noEmit` over `migrated/`; it installs `@typescript/native-preview` with `--no-save` when missing, and the
bench also times `tsgo` and `tsc` alone). Run only those: `npm run bench -- --rows stencil,stencil-standalone,stencilrs,stencilrs+check --runs 3`.
`node smoke/run.mjs stencilrs --out .bench/out/stencilrs+check` smoke-tests the check row's output.

## SSR benchmark (`npm run bench:ssr`)

`bench-ssr.mjs` benchmarks Stencil's built-in server rendering, `renderToString` of a hydrate app, on Ionic 9.0.12, one
row per hydrate app. Each row runs in its own child processes (no state is shared between rows).

| Row | Hydrate app | Needs |
|---|---|---|
| `ionic-published` | `@ionic/core@9.0.12/hydrate` from npm, built by Ionic with Stencil 4 (pinned in `package.json`; npm's latest is 9.0.13) | `npm ci` |
| `stencil5` | `stencil build` with `{ type: 'ssr' }` over `migrated/` (`config/stencil.config.ssr.ts`, copied to `migrated/stencil.ssr.config.ts` by `migrate`) -> `dist/hydrate-stencil/index.js` | `npm run fetch && npm run migrate && npm run build:ssr` |
| `stencilrs` | `dist/hydrate-stencilrs/index.js`, from stencilrs' output (issue #128) | skipped, with a message, while absent |

Rows are data (`ssr-bench/rows.mjs`); `--row stencilrs=<path to a hydrate app>` points one at another file. The pages
(`fragment`: one `ion-button`; `list-50`: `ion-app` / `ion-content` / `ion-list` with 50 `ion-item` holding a label, a
badge and a toggle; `kitchen-sink`: header, toolbar, buttons, cards, inputs, segment, tabs, list) and the render options live
in `ssr-pages.mjs`, which the stencilrs hydrate build imports too. Every row renders every page with `serializeShadowRoot`
`'declarative-shadow-dom'` and `'scoped'`, `prettyHtml: false` and a fixed `buildId` (without it each render stamps a random
`data-stencil-build` on `<html>`, so no two outputs could match); all other options are the defaults.

Steps:

1. **Equality, before any timing.** Each row renders every page and mode once. `stencil5` and `stencilrs` must be
   byte-identical (a difference prints the page, mode and first differing byte, writes `<out>.failed.json` and exits 1 before
   anything is timed). `ionic-published` (Stencil 4) against `stencil5` is reported, not failed: sizes and the first
   differing offset.
2. **Render timing** (`ssr-bench/render.mjs`, fresh process per row): module load (cold `import()`), first render (cold),
   then per page and mode a first render, `--warmup` untimed renders and `--renders` timed ones: median and p95 ms/render, and
   the HTML size. RSS (end and peak) of the process.
3. **Express throughput** (`ssr-bench/server.mjs`, per row and mode): the same minimal app (`GET /` -> `renderToString(page)`
   -> `res.send`, ETag off) under [autocannon](https://github.com/mcollina/autocannon): req/s and p99 latency.

```sh
npm run bench:ssr                                    # every row that exists; 20 renders, 3 warm-up, 4 connections, 5 s
npm run bench:ssr -- --rows stencil5,stencilrs --renders 50 --connections 8 --duration 10
npm run bench:ssr -- --pages list-50 --modes dsd --no-express
```

`--help` lists the options. The table is printed and the JSON (every number above, the equality results, machine, versions and
the options used) is written to `../../site/data/benchmarks-ionic-ssr.json` (`--out`). Rendering is CPU-bound and single-threaded
per row, so on a shared machine the numbers are noisy: the JSON records the load average at the start, and `--note` /
`--machine` describe the run. `ion-range` is left out of the kitchen-sink page: it needs a shadow root and reports a
render error in `scoped` mode on every row.
