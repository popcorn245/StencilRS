# ionic: Ionic Framework core on Stencil v5, the proving ground for stencilrs

[Ionic Framework](https://github.com/ionic-team/ionic-framework)'s `core` (MIT, 94 components, per-mode
iOS / Material Sass, the largest open-source Stencil code base) is the real-world test subject for stencilrs.
This folder fetches it, migrates a copy to Stencil v5, builds it with `stencil build` and checks the result in
headless Chrome. Later issues swap stencilrs in (#61) and benchmark all three builds (#65).

Ionic's source is **never committed** (see `THIRD_PARTY_NOTICES.md`). Everything under it is generated from
upstream plus the checked-in codemod, so the whole thing is reproducible.

```sh
npm ci --ignore-scripts      # Stencil 5.0.0-beta.25, @stencil/sass, ionicons, Playwright
npm run fetch                # clone ionic-team/ionic-framework @ v9.0.12 into upstream/
npm run migrate              # upstream/core -> migrated/ (Stencil v5 source)
npm run build:stencil        # stencil build (v5) -> dist-stencil/, plus css/ and docs.json
npm run smoke                # load dist-stencil in headless Chrome, ios + md, screenshots in smoke/shots/
npm run build:stencil4       # the stock Ionic 9 / Stencil 4.45.4 build -> dist-stencil4/ (reference row)
npm run all                  # fetch, migrate, build:stencil, smoke
```

`npm run smoke -- stencil4` runs the same page against the Stencil 4 build. `--shots <dir>` moves the
screenshots. If the Chromium Playwright expects is not installed, point `CHROME_PATH` at any Chromium
(`npx playwright install chromium` is the proper fix).

## Layout

| Path | What | In git |
|---|---|---|
| `scripts/fetch.mjs` | shallow clone of the pinned tag (`scripts/paths.mjs`) into `upstream/` | yes |
| `scripts/migrate.mjs` | the migration: copy, `stencil migrate`, then our patches | yes |
| `scripts/patches.mjs` | the source patches, each with the reason | yes |
| `config/stencil.config.v4.ts` | trimmed Ionic config; input of `stencil migrate` and of the Stencil 4 build | yes |
| `config/ionicons-css-fix.ts` | one-line CSS repair plugin for ionicons, added to the v5 config | yes |
| `scripts/build.mjs` | `build:stencil` / `build:stencil4`, logs in `logs/` | yes |
| `smoke/` | the smoke page and its Playwright runner | yes |
| `stencil4/package.json` | separate toolchain for the Stencil 4 build (it cannot share `node_modules` with v5) | yes |
| `upstream/` | the clone (untrusted data; nothing in it is installed or run) | **no** |
| `migrated/` | v5 source: `src/`, `stencil.config.ts`, tsconfigs. **#61 adds `vite.config.ts` and `build:stencilrs` against this folder** | **no** |
| `stencil4/stock/` | upstream `core/` unmodified, for the Stencil 4 build | **no** |
| `dist-stencil/`, `dist-stencil4/` | build outputs: `dist/` and `loader/` (lazy), `components/` (standalone), `css/`, `docs.json` | **no** |

Both builds are cold (`enableCache: false`), build the same bundles with the same three output targets (lazy
loader, standalone custom elements, `docs-json`) and write to the same layout, so #65 can time them side by
side. `build:stencil` writes `logs/stencil.log`, `build:stencil4` writes `logs/stencil4.log`; the Sass
deprecation warnings Ionic's `@import`-based Sass triggers (about 80,000 lines per build) are kept in the log
and filtered from the console.

## What was changed in Ionic, and why

Starting point: `core/` of v9.0.12, which Ionic builds with Stencil 4.45.

**Left out of the copy** (`scripts/copy-core.mjs`): `*.spec.ts(x)`, `*.e2e.ts`, every `test/` and `e2e/` folder
(Jest and Playwright tests and their demo pages), `jest.d.ts`, `eslint`, Docker and Vercel files, and
`src/components.d.ts`. The last one is generated by Stencil; upstream's imports `@stencil/core/internal`, which
v5 does not have, so letting it seed the v5 build made every `HTMLIon*Element` type collapse (400+ TypeScript
errors).

**Config** (`config/stencil.config.v4.ts`, diffable against upstream's `core/stencil.config.ts`): the Angular,
React and Vue output targets, `docs-vscode`, `dist-hydrate-script`, the api.txt generator and the Jest `testing`
block are dropped (they write outside `core/` or are not measured), and `docs-json` goes to the build folder.
The bundles, Sass plugin, preamble, global script and `extras` are Ionic's own. The Stencil 4 reference build
uses this same file.

**`stencil migrate`** (Stencil's own codemod, v5.0.0-beta.25) does most of the work: 84 items in 78 files.

| Rule | Items |
|---|---|
| `shadow: true`, `scoped: true`, `shadow: { delegatesFocus: true }` to `encapsulation: { ... }` | 77 |
| `dist` to `loader-bundle`, `esmLoaderPath` to `loaderPath`, `dist-custom-elements` to `standalone` | 3 |
| `extras` to `compat`, `experimentalSlotFixes` removed (`lightDomPatches` is on by default), `enableImportInjection` and `externalRuntime: false` dropped | 4 |

**Our patches** for what it leaves (`scripts/migrate.mjs`, `scripts/patches.mjs`; each must match exactly once,
so an upstream change fails loudly):

1. **`enableCssOnlyComponents: false`.** v5 treats every `.scss` file under `src` as a possible CSS-only
   component and runs Sass on each partial on its own. Ionic's `*.vars.scss` partials rely on variables their
   importer defines, so 12 of them fail with "Undefined variable".
2. **`experimentalScopedSlotChanges`** is removed from the migrated config: `stencil migrate` leaves it in
   `compat`, but v5 has no such option.
3. **tsconfig**: `baseUrl` is an error in TypeScript 6, so it is removed and `src/*` is mapped in `paths` (a
   few files import `src/interface` bare).
4. **JSX is a `VNode`, not an `HTMLElement`.** Three places typed JSX as DOM nodes (`checkbox.tsx`
   `getSVGPath`, `spinner.tsx` `svgs`, `select-option-render.tsx` `renderOptionLabel`) now say `any`.
5. **Invalid CSS that v4 passed through.** v5 parses styles with lightningcss and rejects what browsers
   already ignored. Fixed to what the code obviously meant: `item-divider.ios.scss` (missing comma between two
   `::slotted()`), `item-divider.md.scss` (`::slotted(h3, h4, h5, h6)`), `segment.scss`
   (`:host(.x::-webkit-scrollbar)`), `tab-button.ios.scss` (`::slotted(ion-icon::before)`),
   `accordion-group.md.scss` (`::slotted(x):first-of-type`). The `rtl()` mixin in `ionic.mixins.scss` also
   emitted `.a::before:dir(rtl)`; it no longer emits `:dir(rtl)` rules for selectors with a pseudo-element
   (browsers dropped those anyway). In `ionicons`' `icon.css`, `@supports not selector(a) and selector(b)` is
   parenthesised by a Stencil plugin (`config/ionicons-css-fix.ts`), because that file lives in `node_modules`.
6. **`package.json`** is replaced by a minimal one (v5 validates it against the build output).
7. **Packages**: Ionic's devDependencies the build type-checks against (`@capacitor/*`, `ionicons`, `sass`,
   `tslib`) are pinned in this folder's `package.json`, so nothing is installed inside `upstream/`.

Items 4 and 5 are things any real library moving to v5 will hit; they are the list of v5 incompatibilities
stencilrs has to behave the same on (or report).

## Result

| | Stencil 4.45.4 (stock) | Stencil v5.0.0-beta.25 (migrated) |
|---|---|---|
| Components in `docs.json` | 94 | 94 (same tags) |
| `stencil build`, cold | about 25 s of build, 33 to 44 s with startup | about 21 to 23 s of build, 27 to 34 s with startup |
| Output | 23 MB | 6.6 MB |
| Errors / warnings | none besides Sass deprecations | none besides Sass deprecations and the pre-release notice |
| Smoke page (button, card, list, toggle, modal; ios and md) | all checks pass | all checks pass |
| Screenshots | identical to the pixel | identical to the pixel |

The two builds' screenshots are identical (a pixel diff of all four pairs found no differing pixel). Their
`docs-json` files differ in 15 component entries (union members print in a different order under TypeScript 6,
and style docs are parsed differently); a later issue compares stencilrs' `analyze()` against the v5 one.
